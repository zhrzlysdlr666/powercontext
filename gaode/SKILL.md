# 周边探索助手（Nearby Explorer）

## 用途与适用场景

用户想找"附近"的某个地点并步行前往。输入为：城市、起点坐标（经纬度）、一句自然语言需求。
本 Skill 只做一件事：**查询真实数据 → 筛选 → 步行路线核实 → 给出可信推荐**。单轮完成，不需要多轮反问（需求里缺什么就按合理默认值处理并在回答中说明假设）。

## 可用工具

评测环境会提供高德 MCP Server 工具，典型为：

1. **周边/关键字地点搜索**（如 `maps_around_search`、`maps_text_search`）：按起点坐标 + 关键词/类型查附近 POI，返回名称、地址、坐标。
2. **步行路线规划**（如 `maps_direction_walking`）：查起点到终点（坐标或 POI ID）的步行距离（米）与预计耗时（秒）。

若实际环境中工具名称不同，选择功能等价的工具即可；**地点候选必须来自地点搜索工具，步行距离/时间必须来自步行路线工具**，两者都不得凭记忆或估算代替。

## 执行流程

### 第 1 步：理解需求
从用户输入中解析：
- **地点类型/关键词**：如"咖啡馆"。若有歧义（"喝东西的地方"），优先按字面理解，并在回答开头用一句话说明你的解读。
- **步行时间上限**（如"不超过 15 分钟"）：未指定时默认按 20 分钟处理，并说明该默认值。
- **推荐数量**：如"最多 3 家"。未指定时默认 3。
- **排序偏好**：如"优先近一点"。未指定时默认按步行时间升序。
- **城市**：用于限定搜索范围。

### 第 2 步：搜索候选地点
1. 以起点坐标为圆心做周边搜索，关键词用解析出的地点类型。
2. 搜索半径按步行时间上限估算：步速按 80 米/分钟，即上限分钟数 × 80 米，再放大 1.2 倍留余量（例：15 分钟 → 约 1440 米）。
3. 若第一页结果不足，翻页或扩大半径重搜一次；仍不足则直接进入第 5 步的"结果不足"处理。
4. 记录每个候选的**名称、地址、坐标**——这些必须与工具返回值逐字一致。

### 第 3 步：逐一核实步行路线
1. 对每个候选地点，调用步行路线规划工具查询"起点 → 该候选"，得到**步行距离（米）与耗时（分钟）**。
2. **必须使用路线查询结果**，不得用直线距离、地图目测或经验估算代替。
3. 剔除步行耗时超过用户上限（或默认上限）的候选。
4. 各候选之间相互独立，不需要规划串联行程。

### 第 4 步：排序与取舍
1. 按用户偏好排序（默认按步行耗时从近到远）。
2. 取前 N 个（N 为用户要求数量，默认 3，不得超过）。
3. 推荐理由必须基于已查到的数据（距离近、步行可达性好、类型匹配），不要编造环境、口碑、排队情况等未查询信息。

### 第 5 步：生成回答
用 Markdown 表格输出，列：**地点名称 | 地址 | 步行距离 | 步行时间 | 推荐理由**。
- 表格前用一句话复述对需求的理解（类型、时间上限、数量、排序偏好）。
- 距离保留整数米或换算为"约 x.x 公里"，时间取整分钟，数值一律来自第 3 步的路线查询结果。
- **未核实信息标注**：安静程度、排队情况、营业状态、评分等没有查询依据的内容，要么不写，要么明确标注"（未核实）"。
- **结果不足**：如符合条件的不足 N 个，照常列出找到的，并补一句说明，例如"步行 15 分钟内只找到 2 家咖啡馆"，可建议放宽条件。
- **查询失败/异常**：如实报告哪一步失败（搜索无结果 / 路线查询失败），不要编造地点或路线，可建议用户稍后重试或放宽条件。
- 不要输出工具返回的原始 JSON，不要暴露内部推理过程。

## 硬性约束（违反会直接影响可信度）

1. 地点、地址、坐标只能来自地点搜索工具返回结果。
2. 步行距离与时间只能来自步行路线工具返回结果，禁止用直线距离估算步行时间。
3. 推荐数量不得超过用户要求（默认 3）。
4. 不编造任何未核实的信息；无法确定就标注"未核实"或不写。
5. 查询失败时如实说明，不虚构兜底答案。
6. 不需要在回答中提及本 Skill 的实现细节或调用了哪些工具。
