# 全文索引与中文分词

## 倒排索引的基本结构

倒排索引把「文档 → 词」翻转为「词 → 文档列表」。每个词项（term）记录它出现过的文档编号与该词在文档中的位置信息，查询时按词直接跳到候选文档，避免全表扫描。倒排表通常按词项字典序存储，词项之间用跳表（skip list）加速求交。

词项字典的查找结构决定了查询延迟。常见实现有排序数组 + 二分、前缀压缩的 FST/双数组 Trie。压缩率越高，内存占用越低，但解压带来 CPU 开销，需要按数据规模权衡。

## 分词器决定召回质量

英文按空格切词即可，中文必须借助分词器。按粒度可分三类：单字切分（召回高、噪声大）、词典最大匹配（可控、需要词典）、统计模型分词（效果好、启动慢）。IK 分词器属于词典 + 歧义消解的组合方案，支持 ik_smart（粗粒度）与 ik_max_word（细粒度）两种模式。

建索引与查询必须使用同一种分词模式，否则同一个句子会切成不同的词序列，导致「明明有这个词却搜不到」。这是全文检索最常见的配置错误。

## 相关度打分：BM25 与 TF-IDF

TF-IDF 认为词频越高、文档频率越低，权重越大。BM25 在其上加入饱和函数与文档长度归一化：词频增长到一定程度后收益递减，长文档因为更容易命中而被惩罚。OceanBase/seekdb 的全文检索结果默认按相关度排序，分数可用于过滤低质量召回。

实际调优时，短查询（2-3 个词）用 BM25 更稳；长查询要先做词项加权，否则低频词会主导排序。

## 停止词与词干化

停止词（的、了、是、a、the）对排序无贡献，却占倒排表体积。去掉能显著压缩索引，但会破坏短语查询（"to be or not to be"）。折中方案是保留停止词的位置信息但不建倒排项。

词干化把 running/runs/ran 归并到 run，提高召回；中文没有词干概念，对应手段是同义词表与繁简归一。

## 索引构建的并行度

构建索引是 CPU 密集的分词 + 写 doc_word 行。单线程只能吃满一个核，而一次构建动辄几十万行文档，必须并行。并行度太低构建时间呈线性增长，太高则写放大与合并压力上升。经验值：并行度取 CPU 核数的 1/2 到 2/3，并保证每个分片处理的文档量足够大，避免小分片调度开销占比过高。
