# 检索增强生成（RAG）实践笔记

## 检索质量决定回答上限

RAG 的天花板不是模型，而是召回。模型只能基于拿到手的片段作答，片段错了，提示词写得再漂亮也只产出流畅的胡说。评估 RAG 系统时先看召回率与排序质量，再看生成。

## 切片策略

按固定长度切是最差的做法，它会把一句话拦腰截断。按语义边界切（Markdown 二级标题、代码顶层函数、论文小节）能保证每个切片自洽。切片长度建议 200-500 字：太短缺上下文，太长相关度被稀释、还会挤占上下文窗口。

切片时要保留来源信息（文档名 + 小节标题），它既用于展示引用，也作为检索的辅助信号——把标题拼进正文能明显提升命中率。

## 混合检索

纯向量检索擅长语义相近但用词不同的场景，纯关键词检索擅长精确术语、编号、错误码。两者互补，工业界普遍做混合：关键词召回一批、向量召回一批，再用 RRF（倒数排名融合）合并。RRF 不需要分数归一化，实现简单且鲁棒。

## 重排序

初筛召回 50-100 条，再用交叉编码器（cross-encoder）精排取前 5-10 条，是性价比最高的做法。交叉编码器把 query 和文档拼在一起打分，精度远高于向量内积，代价是不能预计算，只能对少量候选做。

## 上下文组装

把检索结果塞进提示词时，要给每条编号并标注来源，要求模型在回答里引用编号。这既方便核查，也显著降低幻觉。上下文总长度要留出生成空间，别把窗口塞满。

## 评估方法

离线评估用「问题 → 标准答案 → 标准证据」三元组，分别算召回命中率和答案正确率。线上则看用户是否追问、是否复制引用。没有评估集的 RAG 优化全是盲调。
