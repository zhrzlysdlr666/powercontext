## 2. 样例一：只验检索（不开 Dify）

**输入**

```bash
curl -s "http://127.0.0.1:8181/compose?q=机房又断网了&session_id=demo"
```

**预期**

1. `hits` 里至少 1 条来自 `props` / `memes`，且都和「机房 / 网线 / 断网」相关；
2. 每条 hit 带 `score`（`MATCH ... AGAINST` 的相关度，> 0 才说明是全文索引在算分）；
3. 返回体里 `written.table == "turns"`，`turnId` 递增 —— 这一回合已经落库。

**实测**（截图 `evidence/02-search-api.png`）

| kind | title | body（截断） |
| --- | --- | --- |
| 道具 | 一捆网线 | 物理连接万物的信仰道具，机房开光必备 |
| 梗 | 实习生改了一行 | 实习生说只改了一行代码，diff 里出现了四百行… |
| 梗 | Cookie 掉了 | 上周还能免登录，这周突然让你重新登录… |


2. 右上角「预览」或打开「访问入口」，输入：

回答原文（节选，完整见 `06-workflow-run.log`）：

> 铁柱把网线一甩：你那一行，diff 里四百行，三百八是格式化。正说着，屏幕弹出重新登录

**为什么这算「实际读写」而不是「只装组件」**

- **读**：`hits[].score` 是 seekdb 的 `MATCH ... AGAINST` 算出来的相关度，Dify 侧没有任何检索逻辑；
- **写**：每跑一次，`turns` 表多一行，`session_id` 就是这次对话的 conversation UUID
  （`evidence/07-seekdb-turns.json` 里能看到 `6a46ab2d-… / a3d83de4-…` 两条 Dify 写入的记录）。

## 5. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| HTTP 节点报 `Connection refused` | Dify 在容器里，`127.0.0.1` 指的是容器自己 | URL 改成 `http://host.docker.internal:8181/compose` |
| HTTP 节点 422 `Field required: q` | 用了 GET 但参数没渲染出来（params 是 `key: value` 行式格式） | 本 DSL 用的是 POST JSON body，单条模板 `{"input": "...", "session_id": "..."}` |
| HTTP 节点 403 / 私网被拦 | 配了 `SSRF_PROXY_*`，squid 拦截内网地址 | 把 api/worker 的 `SSRF_PROXY_HTTP_URL/HTTPS_URL/ALL_URL` 置空 |
| LLM 报 `CERTIFICATE_VERIFY_FAILED` | 容器走了会做 TLS 拦截的代理 | 用能正常出网的代理，或让该域名直连 |
| `hits` 为空、`stage=like` | 目标实例没有 ik 分词器，MATCH 抛错后降级成 LIKE | 看 `/health` 的 `parser`；装 ik 后重启 |
| 回答里没有素材 | LLM 节点提示词没引用代码节点变量 | 检查提示词里的 `{{#code_node.context#}}` 选择器 |
| `/health` 第一次很慢（数秒） | 首次启动要建库 + 灌 40 条 + 建 4 个索引 | 正常，之后都是毫秒级 |
